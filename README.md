# TLJ 매장 게시판

HTML/CSS/JavaScript 프론트, Python(Flask) API 서버, MySQL로 구성된 매장 게시판입니다. 게시글·회원·첨부파일은 모두 서버(MySQL, 디스크)에 저장되어 여러 기기에서 함께 확인할 수 있습니다.

## 폴더 구성

- `frontend/` — HTML/CSS/JavaScript 정적 파일 (Flask가 그대로 서빙)
- `backend/` — Flask API 서버, MySQL 접근, 첨부파일 저장
- `docker/` — `Dockerfile`, `compose.yaml` (앱 + MySQL + phpMyAdmin)

## 실행

Docker가 실행된 환경에서, 저장소 루트에서:

```sh
docker compose -f docker/compose.yaml up --build -d
```

회원용: http://localhost:8000/ (로그인 필수). 비회원용: http://localhost:8000/guest.html (전체 조회·물품 요청 작성). 종료는 `docker compose -f docker/compose.yaml down`, 데이터까지 초기화하려면 `-v`를 추가합니다.

`web` 서비스는 MySQL(`db` 서비스)이 준비될 때까지 기다렸다가 시작하며, 시작 시 필요한 테이블을 자동으로 만듭니다(`backend/schema.sql`). 게시글 DB는 `db-data` 볼륨에, 첨부파일은 `uploads` 볼륨(`/app/backend/uploads`)에 저장되어 컨테이너를 다시 만들어도 유지됩니다.

`docker/web-env`(`web` 서비스 환경 변수)와 `docker/compose.yaml`의 `MYSQL_ROOT_PASSWORD`는 예시 값입니다. 실제 운영 환경에서는 반드시 값을 변경하세요. `docker/web-env`의 `DB_NAME`/`DB_USER`/`DB_PASSWORD`를 바꾸면 `docker/compose.yaml`의 `db` 서비스 `MYSQL_DATABASE`/`MYSQL_USER`/`MYSQL_PASSWORD`도 같은 값으로 맞춰야 합니다.

## phpMyAdmin 접속

phpMyAdmin은 http://localhost:8080/ 에서 접속합니다. 다른 기기에서는 `http://서버IP:8080/`을 사용합니다. 연결 대상은 Compose의 `db:3306`으로 고정되어 있습니다.

로그인은 MySQL 계정을 사용합니다. `db` 서비스의 `MYSQL_USER` / `MYSQL_PASSWORD`로 로그인하면 `MYSQL_DATABASE` 데이터베이스를 관리할 수 있습니다. 전체 DB 관리가 필요하면 `root`와 `MYSQL_ROOT_PASSWORD`를 사용합니다. 기존 DB 볼륨의 비밀번호를 변경한 경우에는 실제 DB에 설정된 비밀번호를 입력하세요.

이미 서버가 실행 중이라면 아래 명령으로 phpMyAdmin을 추가할 수 있습니다.

```sh
docker compose -f docker/compose.yaml up -d phpmyadmin
```

이미지 및 연결 환경 변수: [phpMyAdmin 공식 Docker 이미지](https://hub.docker.com/_/phpmyadmin).

## 백엔드 구조

- `backend/app.py` — Flask 앱, 프론트 정적 파일 서빙, API 블루프린트 등록
- `backend/db.py` — MySQL 연결, 시작 시 스키마 생성
- `backend/permissions.py` — 게시판·권한 규칙 (프론트 `common.js`와 동일한 규칙을 서버에서도 강제)
- `backend/identity.py` — 로그인 세션(서명된 쿠키), 비회원 식별 쿠키
- `backend/media_store.py` — 첨부파일 검증·저장(디스크)
- `backend/routes/` — `auth`(로그인/회원가입/내 정보), `posts`(게시글 CRUD), `drafts`(임시저장), `users`(관리자), `media`(첨부파일 서빙)

로그인은 여전히 4자리 회원번호만 확인하는 방식이며 비밀번호는 없습니다. 다만 이제 로그인 상태는 서버가 서명한 세션 쿠키(HttpOnly)로 관리되고, 읽기·쓰기·수정·삭제 권한은 매 요청마다 서버에서 다시 검사합니다. 비회원은 서버가 발급하는 별도의 익명 식별 쿠키로 자신이 쓴 물품 요청 글만 수정·삭제할 수 있습니다.

## 구현 기능

- 케이크 생산 / 공지사항 / 필요 물품 요청 게시판, 검색, 30개 단위 페이지 나누기
- 전체 게시글 비회원 조회, 필요 물품 요청 비회원 작성
- 필수 4자리 숫자(앞자리 0 보존)와 이름으로 회원 등록, 중복 번호 방지
- 케이크 생산 제목: 브라우저 현지 시각 기준 내일 날짜 `[yy/mm/dd] 생산목록`
- 일반 텍스트 및 서식 공지, 이미지 첨부·회전·펜 그리기·복원, MP4/WebM 동영상 첨부
- 제목·작성일·업데이트일·작성자 표시, 작성자 수정
- 작성 중 서버에 자동 임시저장: 새로고침 후 같은 회원과 게시판에서 새 글 작성을 열면 복원. 수정 중 임시저장은 같은 글의 수정 화면에서 복원(제목·내용). 첨부파일은 아래 "임시저장과 첨부파일" 참고
- 케이크 생산 글에서만 영수증 인쇄 제공: 글을 열 때 큰 글씨·80mm 기본값 적용, 필요 시 큰 글씨 해제 또는 58mm 선택. 공지사항·물품 요청에는 인쇄 UI 없음
- 모바일 및 PC 반응형 화면

## 임시저장과 첨부파일

새 글 작성 중 추가한 첨부파일은 임시저장 공간에 업로드되며, 글을 저장하는 순간 정식 게시글로 옮겨집니다. 임시저장을 삭제하면 첨부파일도 함께 삭제됩니다.

기존 글을 수정할 때는 제목·내용만 임시저장되고, 첨부파일 추가·삭제·수정(회전/그리기)은 저장 버튼을 누르기 전이라도 즉시 반영됩니다. 즉 수정 화면을 닫거나 "임시저장 삭제"를 눌러도 이미 변경한 첨부파일은 되돌아가지 않습니다. 텍스트만 임시저장/복원 대상입니다.

이미지는 PNG/JPEG/WebP 10MB 이하, 동영상은 MP4/WebM 50MB 이하이며 글당 10개까지 첨부됩니다. 이미지는 최대 변 길이 1800px로 줄어들 수 있습니다. 동영상 재생은 브라우저 코덱 지원에 따릅니다.

영수증 출력은 브라우저 인쇄 창을 사용합니다. 드라이버에서 실제 용지 너비와 여백을 맞추고 머리글/바닥글을 해제하세요. CSS는 297mm 길이를 기본값으로 사용하며 긴 글은 여러 장으로 나뉠 수 있습니다. 직접 ESC/POS 출력 및 자동 절단은 포함하지 않습니다. 실제 프린터 검증이 필요합니다.

## 수동 확인

1. `0123`과 이름으로 가입하고 같은 번호의 중복 가입이 거절되는지 확인합니다.
2. 케이크 새 글 기본 제목을 확인하고 본문 입력 → 임시저장 완료 → 새로고침 → 새 글 작성으로 내용 복원을 확인합니다.
3. 공지에 서식, 이미지, 그림, 회전, 동영상을 추가해 저장하고 상세 화면에서 확인합니다.
4. `/guest.html`에서 물품 요청을 작성하고 새로고침 후 조회·수정합니다. 다른 브라우저(또는 시크릿 창)에서는 같은 글을 수정·삭제할 수 없는지 확인합니다.
5. 31개 게시글에서 30개/1개로 페이지가 나뉘는지 확인합니다.
6. 모바일 화면과 인쇄 미리보기의 58mm/80mm 레이아웃을 확인합니다.
7. 기본 주소와 각 게시판 주소에서 로그인이 필요한지, 미등록 회원번호가 거절되고 이름 없이 로그인되는지, 로그아웃 후 게시판이 숨겨지는지 확인합니다.
8. 로그인한 상태에서 비회원 URL을 열어도 비회원으로 작성되며 생산·일반 공지는 작성할 수 없는지 확인합니다.
9. `docker compose -f docker/compose.yaml restart web`으로 서버만 재시작해도 기존 게시글·회원·첨부파일이 유지되는지 확인합니다.

## 페이지 구성

각 화면은 별도의 HTML 문서이며 게시판 메뉴는 실제 페이지로 이동합니다.

| 화면 | 회원 URL | 비회원 URL |
| --- | --- | --- |
| 로그인 | `/login.html` | — |
| 회원가입 | `/register.html` | — |
| 케이크 생산 | `/cake.html` | `/guest-cake.html` |
| 공지사항 | `/notice.html` | `/guest-notice.html` |
| 필요 물품 요청 | `/request.html` | `/guest-request.html` |

기본 `/` 주소는 로그인 페이지로, 기존 `/guest.html`은 비회원 물품 요청 페이지로 이동합니다. 회원 게시판에 직접 접속하면 로그인 여부를 확인하고, 로그인 후 요청한 게시판으로 돌아갑니다. 게시글 조회·작성·수정은 각각 별도 페이지로 이동합니다. 이미지 그리기 도구만 대화상자로 열립니다.

JavaScript도 `frontend/js` 아래에서 역할별로 분리했습니다: `common.js`(API 호출·세션·공통 함수), `auth.js`(로그인·회원가입), `board.js`(목록·검색·페이지), `editor.js`(작성·임시저장·첨부파일·이미지 편집), `detail.js`(상세·인쇄), `dialogs.js`(공통 대화상자 마크업). 스타일은 `style.css`를 공유합니다.

## 회원 이름 변경

회원 게시판 상단의 **회원정보** 링크 또는 `/profile.html`에서 이름을 변경합니다. 이름은 공백을 제외하고 1~30자로 입력하며 회원번호는 변경하지 않습니다. 저장한 이름은 이후 로그인 표시와 새 글 작성자에 반영됩니다. 기존 게시글의 작성자 표시는 작성 당시 이름을 유지합니다. 회원정보 페이지는 로그인한 본인의 정보만 수정하며, 비로그인 접근은 로그인 페이지로 이동합니다.

## User 관리 및 권한

`docker/web-env`의 `ADMIN_ID`로 지정한 회원번호(기본값 `0026`, 여러 명이면 `0026,0031`처럼 쉼표로 구분)로 로그인하면 회원 게시판 사이드 메뉴에 **User 관리** 링크가 표시됩니다. `/users.html`에서 사용자 검색, 이름 변경, 게시판별 읽기·쓰기·수정·삭제 체크박스를 설정한 뒤 사용자별 **변경 저장**을 누릅니다. `ADMIN_ID`가 아닌 회원은 관리 페이지와 저장 작업에 접근할 수 없습니다(서버가 매 요청마다 다시 확인합니다). 관리자 번호를 자동 생성하지 않으므로 기존 회원 등록 절차를 사용합니다. `ADMIN_ID`를 바꾼 뒤에는 `docker compose -f docker/compose.yaml up -d`로 재적용하세요.

| 기본 권한 | 읽기 | 쓰기 | 수정 | 삭제 |
| --- | --- | --- | --- | --- |
| 케이크 생산 | 허용 | 미허용 | 미허용 | 미허용 |
| 공지사항 | 허용 | 미허용 | 미허용 | 미허용 |
| 필요 물품 요청 | 허용 | 허용 | 허용 | 허용 |

신규 회원과 권한 설정이 없는 기존 회원에게 위 기본값이 적용됩니다. 관리자(`ADMIN_ID`)도 게시판 기본 권한은 동일하며 User 관리에서 본인의 권한을 추가할 수 있습니다. 수정·삭제 권한은 각각 내 글만 허용하거나 다른 사람 글까지 허용할 수 있습니다. 다른 사람 글도 허용하면 내 글 권한이 포함됩니다. 기존 edit/delete 권한은 이전과 동일한 전체 글 범위로 해석합니다. 쓰기와 수정은 별도 권한입니다. 글 상세 화면을 통해 수정·삭제하려면 읽기 권한도 함께 부여하세요. 읽기 권한이 없으면 목록과 상세 내용이 표시되지 않습니다. 변경된 권한은 페이지를 불러오거나 글 열기·작성·수정·삭제 시 서버에서 다시 확인합니다.

기존 비회원 URL에서는 모든 게시판을 조회하고 물품 요청을 작성할 수 있으며, 자신이 쓴 비회원 물품 요청만 수정·삭제합니다(브라우저별 익명 쿠키로 식별). 관리자에 의한 이름 변경도 기존 게시글 작성자 이름을 소급 변경하지 않습니다.

## 회원 삭제

User 관리의 **회원 삭제** 버튼으로 다른 회원을 삭제할 수 있습니다. 관리자만 실행할 수 있으며, docker/web-env의 ADMIN_ID에 지정된 모든 관리자 계정은 삭제할 수 없습니다. 삭제 전 확인 창을 표시합니다.

회원의 기존 게시글과 게시글 첨부파일은 유지하고, 목록·상세·인쇄의 작성자를 `삭제됨`으로 표시합니다. 회원과 게시글의 연결을 해제하므로 같은 회원번호로 재가입해도 이전 글의 작성자가 새 회원으로 바뀌지 않습니다. 해당 회원의 임시저장과 임시 첨부파일은 제거합니다. 삭제된 회원의 로그인 세션은 무효화됩니다.

서버 시작 시 기존 members 테이블에 session_token 컬럼을 자동 추가합니다. 이 기능을 처음 적용하면 기존 사용자는 다시 로그인해야 합니다. DB 변경은 트랜잭션으로 처리되며 테스트는 별도 `tlj_delete_test_` 접두사 DB에서 `tests/test_member_delete.py`로 실행합니다.

## User 관리 목록과 세부 권한

회원 목록은 기본적으로 접힌 상태로 회원번호·이름·관리자 여부만 표시합니다. 행을 선택하면 이름 수정, 권한 설정, 저장·삭제 버튼이 펼쳐집니다. 다시 접어도 입력 중인 값은 유지되며 **변경 저장**을 눌러야 서버에 반영됩니다.

각 게시판은 읽기, 쓰기, 내 글 수정, 다른 사람 글도 수정, 내 글 삭제, 다른 사람 글도 삭제를 설정합니다. 다른 사람 글까지 허용하면 내 글도 허용됩니다. 소유자는 이름이 아닌 회원번호 연결로 판단하고, 비회원 글·삭제된 회원의 글은 다른 사람 글로 취급합니다. 기존 권한과 물품 요청의 기본 전체 글 수정·삭제 권한은 유지합니다. 첨부파일 편집에도 동일한 수정 권한 검사를 적용합니다.

관리자 계정 보호는 화면과 DELETE API 양쪽에서 처리합니다. `ADMIN_ID`에 포함된 계정은 본인이든 다른 관리자든 삭제할 수 없습니다.

웹 외부 포트는 `docker/compose.yaml`의 `web.ports`에 있는 `8000:8000`의 앞 숫자입니다. 컨테이너 내부 포트 기본값은 `backend/config.py`의 `PORT=8000`이며, 외부 포트만 바꾸려면 예를 들어 `9000:8000`으로 변경합니다.
## 게시글 페이지와 링크 전달

모든 게시판은 목록에서 글을 선택하면 `/post.html?id=게시글ID`로 이동합니다. 비회원 조회는 `/guest-post.html?id=게시글ID`입니다. 상세 페이지는 해당 글만 보여주며 새로고침과 직접 URL 접속을 지원합니다. 회원용 글 주소에 비로그인 상태로 접속하면 로그인 후 같은 글로 돌아갑니다.

상세 페이지의 **링크 복사**는 비회원도 볼 수 있는 `/guest-post.html?id=...` 주소를 복사합니다. 이미지·동영상도 공유 페이지에서 표시됩니다. 클립보드를 사용할 수 없는 HTTP 환경에서는 링크 입력란을 표시해 직접 복사할 수 있습니다. 다른 기기에 전달할 때에는 localhost 대신 해당 기기에서 접속 가능한 서버 주소로 사이트에 접속해 링크를 복사하세요.

작성 페이지는 `/edit.html?board=cake|notice|request`, 수정 페이지는 `/edit.html?board=게시판&id=게시글ID`입니다. 비회원은 `/guest-edit.html`을 사용하며 물품 요청의 기존 권한 규칙이 적용됩니다. 저장 후 해당 글의 상세 페이지로 이동하고, 수정 저장이 끝난 임시저장은 정리합니다. 케이크 생산 상세 페이지의 큰 글씨·80mm 인쇄 기본값도 유지합니다.

페이지 이동·공유 주소·로그인 복귀·복사 대체 UI·인쇄 기본값 검사는 `node tests/test_post_pages.cjs`로 실행합니다.
