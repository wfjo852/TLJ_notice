# TLJ 매장 게시판

HTML/CSS/JavaScript 프론트와 Python 정적 파일 서버입니다. MySQL 및 서버 API는 프론트 확인 후 연결할 예정입니다.

## 실행

Docker가 실행된 환경에서:

```sh
docker compose up --build -d
```

회원용: http://localhost:8000/ (로그인 필수). 비회원용: http://localhost:8000/guest.html (전체 조회·물품 요청 작성). 종료는 `docker compose down`입니다.

Python 3.10 이상 설치 환경에서는 `python server.py`로도 실행할 수 있습니다. 외부 패키지는 필요하지 않습니다.

## 구현 기능

- 케이크 생산 / 공지사항 / 필요 물품 요청 게시판, 검색, 30개 단위 페이지 나누기
- 전체 게시글 비회원 조회, 필요 물품 요청 비회원 작성
- 필수 4자리 숫자(앞자리 0 보존)와 이름으로 회원 등록, 중복 번호 방지
- 케이크 생산 제목: 브라우저 현지 시각 기준 내일 날짜 `[yy/mm/dd] 생산목록`
- 일반 텍스트 및 서식 공지, 이미지 첨부·회전·펜 그리기·복원, MP4/WebM 동영상 첨부
- 제목·작성일·업데이트일·작성자 표시, 작성자 수정
- 작성 중 IndexedDB 자동 저장: 새로고침 후 같은 회원과 게시판에서 새 글 작성을 열면 복원. 수정 중 임시저장은 같은 글의 수정 화면에서 복원
- 케이크 생산 글에서만 영수증 인쇄 제공: 글을 열 때 큰 글씨·80mm 기본값 적용, 필요 시 큰 글씨 해제 또는 58mm 선택. 공지사항·물품 요청에는 인쇄 UI 없음
- 모바일 및 PC 반응형 화면

## 현재 단계의 범위

게시글, 첨부파일, 회원과 임시저장은 현재 브라우저의 IndexedDB에 저장됩니다. 브라우저 데이터 삭제 시 사라지며 다른 기기와 공유되지 않습니다. 로그인은 등록된 4자리 회원번호만 확인하는 프론트 기능입니다. 이름은 회원가입할 때만 필수로 입력합니다. 서버 인증/권한 검증은 아직 연결되지 않았습니다. 로그인 상태는 탭의 sessionStorage에 저장되어 새로고침 시 유지되고 로그아웃 시 삭제됩니다. 비회원 URL에서는 회원 로그인 상태를 사용하지 않습니다. 비회원 글은 작성한 브라우저의 비회원 상태에서 수정할 수 있습니다. 공유 서비스로 운영하기 전 Python API, MySQL, 서버의 인증·권한 검증과 파일 저장을 구현해야 합니다.

이미지는 PNG/JPEG/WebP 10MB 이하, 동영상은 MP4/WebM 50MB 이하이며 글당 10개까지 첨부됩니다. 이미지는 최대 변 길이 1800px로 줄어들 수 있습니다. 브라우저 저장 공간 부족 시 저장 실패를 알립니다. 동영상 재생은 브라우저 코덱 지원에 따릅니다.

영수증 출력은 브라우저 인쇄 창을 사용합니다. 드라이버에서 실제 용지 너비와 여백을 맞추고 머리글/바닥글을 해제하세요. CSS는 297mm 길이를 기본값으로 사용하며 긴 글은 여러 장으로 나뉠 수 있습니다. 직접 ESC/POS 출력 및 자동 절단은 포함하지 않습니다. 실제 프린터 검증이 필요합니다.

## 수동 확인

1. `0123`과 이름으로 가입하고 같은 번호의 중복 가입이 거절되는지 확인합니다.
2. 케이크 새 글 기본 제목을 확인하고 본문 입력 → 임시저장 완료 → 새로고침 → 새 글 작성으로 내용 복원을 확인합니다.
3. 공지에 서식, 이미지, 그림, 회전, 동영상을 추가해 저장하고 상세 화면에서 확인합니다.
4. `/guest.html`에서 물품 요청을 작성하고 새로고침 후 조회·수정합니다.
5. 31개 게시글에서 30개/1개로 페이지가 나뉘는지 확인합니다.
6. 모바일 화면과 인쇄 미리보기의 58mm/80mm 레이아웃을 확인합니다.

7. 기본 주소와 각 게시판 주소에서 로그인이 필요한지, 미등록 회원번호가 거절되고 이름 없이 로그인되는지, 로그아웃 후 게시판이 숨겨지는지 확인합니다.
8. 로그인한 상태에서 비회원 URL을 열어도 비회원으로 작성되며 생산·일반 공지는 작성할 수 없는지 확인합니다.

회귀 검증은 Node.js 환경에서 `node tests/pages.cjs`로 실행합니다. 페이지 연결, 로그인, 회원가입, 비회원 권한, 인쇄 기본값 및 임시저장 복원을 확인합니다. DOM과 저장소를 대체한 로직 검사이며 실제 브라우저 검증은 별도입니다.

## 페이지 구성

각 화면은 별도의 HTML 문서이며 게시판 메뉴는 실제 페이지로 이동합니다.

| 화면 | 회원 URL | 비회원 URL |
| --- | --- | --- |
| 로그인 | `/login.html` | — |
| 회원가입 | `/register.html` | — |
| 케이크 생산 | `/cake.html` | `/guest-cake.html` |
| 공지사항 | `/notice.html` | `/guest-notice.html` |
| 필요 물품 요청 | `/request.html` | `/guest-request.html` |

기본 `/` 주소는 로그인 페이지로, 기존 `/guest.html`은 비회원 물품 요청 페이지로 이동합니다. 회원 게시판에 직접 접속하면 로그인 여부를 확인하고, 로그인 후 요청한 게시판으로 돌아갑니다. 게시글 작성·상세 보기는 각 게시판에서 대화상자로 열립니다.

JavaScript도 `frontend/js` 아래에서 역할별로 분리했습니다: `common.js`(저장소·세션·공통 함수), `auth.js`(로그인·회원가입), `board.js`(목록·검색·페이지), `editor.js`(작성·임시저장·이미지 편집), `detail.js`(상세·인쇄), `dialogs.js`(공통 대화상자 마크업). 스타일은 `style.css`를 공유합니다.
## 회원 이름 변경

회원 게시판 상단의 **회원정보** 링크 또는 `/profile.html`에서 이름을 변경합니다. 이름은 공백을 제외하고 1~30자로 입력하며 회원번호는 변경하지 않습니다. 저장한 이름은 이후 로그인 표시와 새 글 작성자에 반영됩니다. 기존 게시글의 작성자 표시는 작성 당시 이름을 유지합니다. 회원정보 페이지는 로그인한 본인의 정보만 수정하며, 비로그인 접근은 로그인 페이지로 이동합니다.

## User 관리 및 권한

`0026`으로 로그인하면 회원 게시판 사이드 메뉴에 **User 관리** 링크가 표시됩니다. `/users.html`에서 사용자 검색, 이름 변경, 게시판별 읽기·쓰기·수정·삭제 체크박스를 설정한 뒤 사용자별 **변경 저장**을 누릅니다. `0026` 이외의 회원은 관리 페이지와 저장 작업에 접근할 수 없습니다. 관리자 번호를 자동 생성하지 않으므로 기존 회원 등록 절차를 사용합니다.

| 기본 권한 | 읽기 | 쓰기 | 수정 | 삭제 |
| --- | --- | --- | --- | --- |
| 케이크 생산 | 허용 | 미허용 | 미허용 | 미허용 |
| 공지사항 | 허용 | 미허용 | 미허용 | 미허용 |
| 필요 물품 요청 | 허용 | 허용 | 허용 | 허용 |

신규 회원과 권한 설정이 없는 기존 회원에게 위 기본값이 적용됩니다. `0026`도 게시판 기본 권한은 동일하며 User 관리에서 본인의 권한을 추가할 수 있습니다. 수정·삭제 권한은 해당 게시판의 모든 글에 적용됩니다. 쓰기와 수정은 별도 권한입니다. 글 상세 화면을 통해 수정·삭제하려면 읽기 권한도 함께 부여하세요. 읽기 권한이 없으면 목록과 상세 내용이 표시되지 않습니다. 변경된 권한은 페이지를 불러오거나 글 열기·작성·수정·삭제 시 다시 확인합니다.

기존 비회원 URL에서는 모든 게시판을 조회하고 물품 요청을 작성할 수 있으며, 작성한 브라우저에서 자신의 비회원 물품 요청만 수정·삭제합니다. 관리자에 의한 이름 변경도 기존 게시글 작성자 이름을 소급 변경하지 않습니다.

현재는 IndexedDB에 저장하는 프론트 단계입니다. 권한은 현재 브라우저에서만 공유되고, 회원번호만으로 로그인하므로 서버 보안 경계가 아닙니다. 실제 서비스에는 Python API 및 MySQL 기반 인증·권한 검증이 필요합니다. `tests/pages.cjs`에서 기본 권한, 0026 접근 제한, 이름·권한 저장, 권한 회수 및 삭제 로직을 함께 검증합니다.
